## High — fix before anyone relies on it

### H1. Any driver can control any trip
`backend/src/routes/trips.ts:140-206` — `/start`, `/pause`, `/resume`, `/complete` check `requireDriver` but not that the trip is theirs (only `PATCH /:id/status` does). `/stops/:stopId/arrive` only checks that *some* token is present.
**Scenario:** driver A sends `POST /api/trips/42/complete` for driver B's live trip; it vanishes from passengers' maps.
**Fix:** one shared `assertOwnsTrip(tripId, driverId)` used by all five handlers (and admins allowed explicitly if wanted).

### H2. Any logged-in user can move any bus
`backend/src/routes/buses.ts:88` — `POST /buses/:id/location` only needs a valid token.
**Scenario:** any driver posts coordinates for every bus; passengers see buses teleport.
**Fix:** require driver role and that `buses.current_trip_id` is an `En Route` trip owned by `req.user.driver_id`.

### H3. Passenger complaints are public; reports can be pinned on any driver
`backend/src/routes/reports.ts:8` — `GET /api/reports` has no auth and returns every report's message with driver names. `POST` accepts any `driver_id` from anonymous callers, with no length or type checks.
**Fix:** `GET` → `authenticateToken, requireAdmin`. On `POST`, derive `driver_id` from `trip_id` server-side, validate `report_type` against a list, cap `message` length.

### H4. Rate limiter puts all users in one bucket on Render
`backend/src/app.ts` never sets `app.set('trust proxy', …)`, so behind Render's proxy `req.ip` is the proxy, not the user.
**Scenario:** 10 logins/minute *in total* across all drivers and admins; 100 requests/minute across all passengers → everyone gets 429.
**Fix:** `app.set('trust proxy', 1)`.

### H5. Offline GPS queue replays stale positions over live ones
`driver-app/hooks/useDriverLocation.ts:323` + `backend/src/routes/buses.ts:118` — after each successful live update, the task sends the *oldest* queued point, and the backend overwrites unconditionally.
**Scenario:** driver loses signal for 10 minutes (40 queued points). After reconnecting, every 15 s the bus jumps back to an old spot; it takes ~10 minutes of drain before the map is right.
**Fix:** backend `UPDATE … WHERE last_updated IS NULL OR last_updated < $4` (store history separately if wanted), and/or drain the queue *before* sending the live point.

### H6. GPS timestamps are 5 h 30 m in the future
`driver-app/hooks/useDriverLocation.ts:84` — `formatTimestamp()` builds local time with **no timezone** (`2026-11-24T10:00:00`). The server runs in UTC and parses it as UTC.
**Fix:** use `new Date(location.timestamp).toISOString()` (also the real fix time, not the send time).

### H7. Automatic stop detection never records an arrival
`driver-app/lib/queue.ts:18` rejects arrivals unless `stop_id` is a number, but `stop_id` comes from Postgres `bigint` columns, which node-postgres returns as **strings** (`"3"`). Every geofence arrival is dropped with "Invalid arrival data".
Also, the backend ignores the queued `actual_arrival_time` and stamps `NOW()` at sync time (`trips.ts:197`).
**Fix:** `Number(stop.stop_id)` when building the tracked stops (or set a pg type parser for int8), and accept/validate the client's arrival time.

### H8. Route-stop editor in the dashboard calls endpoints that don't exist
`admin-dashboard/src/lib/apiClient.ts:98-115` calls `POST /routes/:id/stops`, `PUT|DELETE /routes/:id/stops/:routeStopId`. The backend only has `GET /routes/:id/stops`, and that response doesn't include `route_stop_id` **(verified by comparing all client calls to backend routes)**.
**Scenario:** admins can't add, edit or remove stops on a route from the dashboard → 404.
**Fix:** add the three admin routes in `routes.ts` and return `rs.route_stop_id` from the GET.

### H9. Passenger "Report" screen can't load trips
`passenger-app/app/report.tsx:26` calls `GET /api/trips`, which requires a token passengers don't have → 401 → empty list → the form can't be submitted.
**Fix:** a public, minimal `GET /api/trips/active` (trip_id, route, bus_no only), or let reports reference `bus_id`/`route_id` instead.

### H10. Dashboard logs out on every page reload
`admin-dashboard/src/lib/apiClient.ts:15-16` — `getToken()` *removes* the stored token and then reads it, so it always returns `null` after a refresh.
**Fix:** delete the `removeItem` line (or move tokens to an httpOnly cookie, see L5).

### H11. Next.js 14.2.35 has a critical advisory
`npm audit --omit=dev` in `admin-dashboard`: 1 critical (`next`), 8 high (transitive). Backend: 0.
**Fix:** upgrade Next (and `eslint-config-next`), then re-run audit. `supertest` belongs in devDependencies.

## Low

- **L1** `validateRoute` / `validateDriver` exist but aren't used; several `PUT`s return `200` with an empty body when the row doesn't exist (`buses`, `routes`, `trips`, `schedules`).
- **L2** Driver login logs phone numbers at `info` (`auth.ts:15-64`); the driver app logs every request in production.
- **L3** `PATCH /drivers/me` lets a driver change their login phone with no format check.
- **L4** The background task uses `locations[0]` (the oldest in a batch) instead of the newest.
- **L5** Tokens live in `localStorage` (dashboard) and `AsyncStorage` (driver). Prefer an httpOnly cookie and `expo-secure-store`.
- **L6** The seed isn't idempotent: `ON CONFLICT DO NOTHING` has no unique constraint on `stops` or `route_stops`, so running it twice duplicates them.
- **L7** No security headers (`helmet`); the dashboard's `middleware.ts` does nothing.
- **L8** A Supabase anon key for project `ygxktvxliwmayezqlsgt` is in git history. Anon keys are public by design, but pause or delete that old project if it's unused.
- **L9** Stale comment in `auth.ts:101` points to a `/api/admin/setup-password` route that doesn't exist.
- **L10** `%` and `_` in search input act as wildcards in `ILIKE` (`routes.ts:183`, `stops.ts:48`).
